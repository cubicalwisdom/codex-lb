# Design

## Root cause

The bridge reader permits up to `stream_idle_timeout_seconds` (600 seconds by default) without an upstream message. A second request waits only `proxy_admission_wait_timeout_seconds` (10 seconds by default) for the same session's response-create semaphore. Before this change, that timeout logged the pending request age and rejected the waiter but left the stale session registered. Live evidence showed pending ages of 311–363 seconds and repeated reuse of the same hashed bridge keys.

## Recovery rule

Port the guarded retirement threshold from upstream PR #1156 without importing its unrelated TTFT persistence/dashboard work. Each request state records the monotonic time at which it actually acquires the response-create gate and clears that timestamp when the gate is released. Total request age is diagnostic only: routing or capacity delay before gate acquisition cannot make a newly sent request immediately eligible. Each request also records a monotonic `upstream_event_seen` marker as soon as HTTP bridge upstream input is matched to it, before retry, typeless-error, or terminal-event branching. Replay preparation may reset `response_id` and `response_event_count`, but it never resets this marker.

At gate timeout, pending ids and ages may be snapshotted for diagnostics, but that snapshot never authorizes retirement. The final decision is made while holding the session lifecycle lock and revalidated under the pending lock. A state is eligible only when it:

- is a normal visible HTTP request (`skip_request_log` is false);
- still owns the response-create gate and awaits `response.created`;
- has never been matched to an upstream event and has no downstream-visible output;
- has held the response-create gate for at least the configured threshold.

The eligible generation is permanently tombstoned and marked closed. Before the lifecycle lock is released, retirement synchronously snapshots and calls `cancel()` on the reader and every registered active-send child, with a current-task guard, so no already-runnable activity can produce post-tombstone side effects while the close child is waiting to start. Registry removal then uses expected-generation detach so a replacement generation cannot be removed accidentally. All locks are released before a bounded, shielded close child awaits those tasks, fails and removes pending requests with `stream_incomplete`, terminalizes their queues, and releases response-create, admission, account-response-create, reservation, and alias ownership. Cancellation of the waiter-side retirement caller cannot abandon the detached generation because the close child remains tracked to completion.

Terminal account-lease release, durable-ownership release, and upstream-socket close are owned by a separate tracked settlement child that starts before the close path's first await. The three resources settle in independent retry loops so one blocked or transiently failing operation cannot delay either the others or pending-request and gate cleanup. A session reference is cleared only after the matching external release succeeds, and upstream close is marked complete only after success. Direct close waits for this child only through the existing bounded shielded budget; timeout or caller cancellation leaves the child and unresolved references tracked. The bridge background drain includes terminal-settlement children and waits for them without a task awaiting itself.

Reconnect attempts are serialized by a dedicated per-session reconnect lock so two provisional handoffs cannot snapshot the same old socket/reader and later overwrite or release each other's installed resources. Within that serialized operation, reconnect rejects a tombstoned generation before account selection or socket open. Until the final lifecycle commit, the provisional socket and newly acquired lease remain local ownership while the installed socket and lease remain session ownership. Cancellation, including cancellation raised inside a named refresh/proxy-error handler or repeated while cleanup is running, transfers the provisional resources to a separately tracked shielded cleanup child before preserving the original failure. That child retries each unresolved provisional resource and continues in the background after the bounded foreground wait. A reused session lease is never provisional and is retained on every pre-install terminal failure.

The no-await final lifecycle commit chooses one owner for every installed and provisional handle. If retirement wins first, reconnect rejects without changing session ownership and provisional cleanup alone settles the losing socket and new lease; terminal settlement alone owns the old installed handles. If reconnect wins, it atomically captures the exact installed socket and lease, installs the provisional replacement, and starts one tracked displaced-resource settlement child before releasing lifecycle. That child closes the displaced socket and releases a displaced lease through independent retry loops, never clears replacement session fields, and excludes an identical lease reused by the replacement. Later retirement therefore observes only the newly installed handles.

Initial submission and every replay/resend path register their actual `send_text` child under the lifecycle lock after final generation validation, then await network I/O without holding the lock. Initial submission uses a lock-held registration helper to avoid lifecycle re-entry; retry paths use the same registration plus an outer active-generation helper. Retirement can therefore acquire lifecycle even when the initial network write hangs, mark the generation terminal, and synchronously cancel the complete active-send snapshot. The timed-out waiter still receives the existing stable `response_create_gate_timeout` error; a later client retry may create a new generation, but the retired generation can never reconnect, replay, resend, or reacquire ownership.

## Safety boundary

The default 300-second threshold matches upstream. A healthy long stream has already received `response.created`, released the gate, produced downstream-visible output, or set the immutable upstream-event marker, so it cannot satisfy the predicate. A request that is old because it waited in routing or capacity recovery but only recently acquired the gate is also ineligible. Synthetic prewarm requests and non-HTTP work remain excluded. Existing reader-originated cleanup continues to run inside its caller-held lifecycle lock without re-entering that lock; only stuck-gate retirement applies the permanent tombstone. No prompt, raw affinity key, or account secret is logged.
