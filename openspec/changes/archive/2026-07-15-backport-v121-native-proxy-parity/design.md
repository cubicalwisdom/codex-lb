## Context

`codexneo-portable-windows` contains a verified Responses Lite and GPT-5.6 parity layer, but it diverged from upstream after the `v1.20.1` base. The portable runtime is a single local Electron-owned process today, yet its bridge code already supports owner forwarding and must remain safe for a later multi-instance deployment.

## Goals / Non-Goals

**Goals:**

- Backport the narrow v1.21 wire contracts that affect native Codex and multi-agent requests.
- Preserve field omission, stable affinity, and the native Codex client identity across direct, retry, and owner-forward egress.
- Prevent unsafe fresh replay and unsafe internal header forwarding.
- Let large downstream WebSocket frames reach the existing application-level guard and use a fail-fast OpenAI error rather than a protocol disconnect or retry-inducing 413.

**Non-Goals:**

- Do not merge the v1.21 release, introduce its migrations, enable Fast Mode policy, reset credits, automations, model sources, or multi-replica scheduling.
- Do not restart Codex Desktop or change the live portable configuration.

## Decisions

- **Selective backport, not file replacement.** The portable branch has intentional Responses lifecycle, retention, and Windows changes. Port only the relevant behavior and regression cases into the current structure.
- **Preserve client omission at every forwarding boundary.** `ResponsesRequest` will expose a forwarding serializer that omits defaulted `tools` when the caller omitted the field; owner-forward payloads and signatures use it. This protects multi-agent-v2/Lite payloads, which reject synthesized empty tools.
- **Canonicalize only outbound upstream identity.** Native Codex traffic retains its valid identity; OpenAI-compatible callers are normalized to the Codex CLI fingerprint immediately before upstream HTTP/WebSocket egress. The selected account identity replaces any caller-supplied account value.
- **Fail closed after observable output.** Full WebSocket replays are allowed only for self-contained request bodies and before any sequenced downstream frame. Tool-output deltas and exposed sequences produce the existing retryable continuity failure instead of a fabricated fresh turn.
- **Strip then rebuild internal-forward headers.** Owner forwarding filters client headers, removes hop-by-hop and bridge-reserved names, restores only the downstream API-key authorization needed by the owner, then adds signed internal context.
- **Use the established app-level size guard.** Raise downstream WebSocket ingress to 128 MiB through the normal CLI and switch a remaining oversized `response.create` error from 413 to 400; no reverse-proxy/deployment settings are changed in this portable slice.

## Risks / Trade-offs

- **Upstream drift** → keep changes narrow, add product-path regressions, and compare only the named v1.21 contracts.
- **Replay correctness** → reject unsafe deltas/replays rather than attempting best-effort reconstruction.
- **Portable activation mismatch** → mirror every changed runtime module into the portable app and verify SHA-256 parity; do not claim activation until the user performs a normal portable restart.
- **Header filtering could break owner authentication** → explicitly restore only `Authorization` after filtering and test that JSON content type is generated by aiohttp.

## Migration Plan

1. Add the contracts and focused regressions in source.
2. Run focused proxy, WebSocket, bridge, CLI, and OpenSpec validation.
3. Mirror changed Python modules into both portable runtime code roots and verify hashes/compilation.
4. Leave the running portable backend and Codex Desktop untouched; the user’s next normal portable restart activates the bundle.
